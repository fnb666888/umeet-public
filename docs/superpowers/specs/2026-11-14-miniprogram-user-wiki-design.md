## 方案选择

采用现有原生 TypeScript/WXML/WXSS 小程序，连接新版 NestJS/MySQL 服务，与网站共用用户 ID、社区内容、私信及 Wiki 数据。复用现有账号、权限、审核、版本和目录规则。

用户已在选项中选择小程序完整贡献流程。另一种“小程序轻量修改、复杂编辑回网站”的方案不作为本轮交付目标。整站 WebView 无法满足已选的原生编辑和页面交互，因此不作为主要实现方式。

本方案以下导航、接口边界和实现顺序为工程建议，随完整方案确认；具体代码结构、组件拆分和测试工具由实施者决定。

## UI：同一个产品的设计风格

网站当前的样式与组件是设计依据，以 `rebuild/apps/web/public/demo/css/style.css`、社区样式和 Wiki 样式为准。统一品牌色、语义色、字体层级、字重、留白、圆角、边框、阴影、线性图标、按钮层级、标签和表单状态；深浅主题沿用网站的语义规则。

社区卡片的信息顺序、点赞收藏反馈、弹窗动作顺序、Wiki 标题与正文层级、空状态与错误提示也应一致。移动适配只调整布局密度和交互方式，不另创视觉风格。

当前网站的品牌蓝为 `#3568d4`，正文 `#1f2328`，次级正文 `#636b74`，边框 `#e3e6ea`，主要表面为白色；实现时从网站设计变量取得这些值，并保持两端一致，而非另写近似色值。

React 组件不直接复制为 WXML。提取一份跨端语义设计变量，Web 和小程序分别映射为 CSS 与 WXSS；只对需要共用的现有变量做整理，不同时重设计网站。长内容、弹层、底部安全区、键盘遮挡、触控范围使用原生适配。

建议底栏为“社区 / Wiki / 消息 / 我的”。原“校园”中的指南通过 Wiki 的校园手册目录承接，保留已发布内容的可访问入口。社区发现、搜索和板块列表设在社区内，不占用额外底栏。

## 接口与账号统一

- 小程序只使用新版业务身份及一套会话服务；全局请求、个人页、发帖、私信、Wiki 均从这一处取得当前用户。
- 与网站关联须显式验证已有账号；沿用微信身份绑定的冲突检测，不能按昵称或未经验证的邮箱自动合并。
- 微信 code 由服务端向微信验证；应用密钥仅在服务端。真实微信能力未配置时明确禁用并说明，不伪造成功。
- 小程序独立 Bearer 会话继续由服务端管理，不复制网站 HttpOnly Cookie。网站五账号选择器的设备授权不直接复用为微信端身份。
- 登录过期、退出、账号变更时统一清除身份相关内存缓存；本地草稿按用户 ID 隔离。已有未标明作者的旧草稿不自动归属任一登录账号。
- 页面通过统一的移动端接口访问新版现有服务。补齐必要的 GET/POST/PUT/DELETE 白名单，复用服务端校验、幂等、权限和数据可见性规则。
- 网站主社区实际使用 `DemoSnapshotsService` 的实体与操作规则；小程序必须访问同一内容源，不另接到一套相似但不互通的帖子库。按需抽取共享查询和移动端分页投影，保留同一写入规则。
- 域名和环境集中配置，开发联调指向本地隔离后端，正式构建使用明确的 HTTPS 接口地址。旧接口停用后不静默回退到旧数据。
- 列表使用有边界的分页请求；页面不下载全站快照、所有评论或完整私信历史。用户态接口禁止公共缓存。

## 普通用户功能闭环

1. 未登录浏览、搜索、板块发现；登录后贡献，权限不足和受限账号有明确反馈。
2. 帖子列表、详情、回复、点赞、收藏、举报、分享链接与用户主页，复用网站当前规则。
3. 发帖与编辑、图片、标签、板块专有字段、原账号草稿恢复；失败保留输入，提交幂等防重复。微信临时图片路径不视为已持久保存资源。
4. 个人资料、我的发布、回复、收藏、草稿、账号与微信绑定、退出。
5. 私信会话、消息请求、未读、分页、发送重试、屏蔽和举报；系统通知与私信在消息页清楚区分。
6. 深层链接能进入对应帖子、词条或路线；内容隐藏、删除、权限变化及网络失败都有可恢复状态。
7. 普通用户的开设板块申请、个人申请进度、邀请查看与接受、管理记录和申诉等入口按网站现有能力接入；实际审核和治理操作仍在网页后台。旧学校认证流程不替代新版权限规则，不虚构新版后端没有的学校和认证数据。

本轮不在小程序中实现管理员后台。管理身份在小程序使用普通用户功能时，实际权限仍由服务端判断；无需在产品中暴露测试角色模拟开关。

## Wiki 阅读与贡献

- 沿用已确认的全站共享词条、社区收录目录、独立学习路线；物理学的基础、近似、应用三分支与校园手册均可阅读。
- 支持搜索、别名、词条内部链接、目录、路线目标及逐步阅读、前置和近似等四类关系与条件说明。
- Markdown 正文正确显示标题、列表、表格、图片、代码、行内与块公式。长表格和长公式可横向滚动，不挤出整页。
- 创建和修改采用内容模板、Markdown 输入与预览；支持关系目标检索、条件、解释和依据；不以原始页面 ID 让用户手填关系。
- 原生编辑页面支持服务器私人草稿、明确保存状态、失败重试和重新进入恢复。断网时保留按账号隔离的未同步副本，不能把本机副本称为已同步。
- 普通用户提交待审版本，查看本人贡献状态、退回理由、继续修改重提；已发布版本不被未审稿覆盖。
- 同时修改或基于旧正文提交时展示冲突，保留作者输入，核对后重提。普通用户不能在小程序绕过网页的审核规则。
- 阅读公开历史和差异，提交讨论与纠错；隐藏词条与失效引用显示明确提示，草稿与待审正文不进入公开搜索。
- 小程序 Markdown/公式渲染技术由实施者先做最小兼容验证再选定；必须以物理公式、长表格和校园步骤样例作为通过门槛，不能以漏显公式的普通文本渲染替代验收。解析器限制外链和不安全内容，不执行作者脚本。

## 顺序与验收

按“统一身份与环境 → 对齐视觉基础与社区闭环 → 私信和个人页 → Wiki 阅读 → Wiki 编辑和草稿 → 全流程验收”实施。这是施工顺序，完整选定能力跑通后才交付验收。

验收至少覆盖：网站和小程序同账号同数据；普通用户双账号数据隔离；重复提交与会话过期；发帖图片与草稿；双用户私信；物理与校园手册样例；Wiki 关系、目录和学习路线；待审、退回、冲突与草稿恢复；断网和失败输入保护；网站与小程序并排的视觉核对；小屏、键盘、安全区和深浅主题。

TypeScript 构建、WXML/WXSS、资源与事件检查、真实后端集成及开发者工具自动化分别记录。开发者工具登录不等于应用真实微信登录通过；真机登录、域名、上传和微信分享属于设备验收，未验证的项目明确记录。

## 范围边界

本轮开发与测试先使用本地隔离环境；不因本方案自动发布或部署线上，不导入网站测试账号密码至小程序包，不迁移旧生产数据库，不替用户完成微信平台权限申请。旧稿件与本地数据不静默删除。正式版本发布另行执行。
