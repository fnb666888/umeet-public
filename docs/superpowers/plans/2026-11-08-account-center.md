# 账号中心实施计划

## 已确认方向

根据用户确认的优化建议，在现有 React、NestJS 和 MySQL 上完善第一阶段账号体验。沿用固定用户 ID，保留现有内容归属与登录凭据。网页继续使用邮箱验证码。用户名独立于昵称和密码凭据。邮箱换绑通过先验证新增、再移除旧邮箱完成，保留至少一种有效登录凭据。敏感操作要求近期重新验证。

## 实施任务

- [x] 增量数据库迁移，为用户增加唯一用户名、首次资料完成时间，为会话增加公开管理 ID、设备描述、创建及活动时间，兼容历史数据。
- [x] 新增账号概览、首次资料完善、邮箱解绑、设备列表与撤销接口。复用现有 OTP 登录及绑定能力，保护唯一性、账号所有权、并发操作与最后凭据。
- [x] 补微信原生身份绑定接口，复用服务端 code2Session 验证，冲突时明确拒绝。核对现有小程序与重建后端的兼容情况。
- [x] React 账号中心接入概览、资料完善、邮箱验证与管理、重新验证、设备退出。邮箱 OTP 后原页面保留，新用户显示资料引导。
- [x] 完善接口和浏览器回归，覆盖旧账号、首次使用、邮箱绑定冲突、最后凭据保护、跨用户设备访问与会话撤销。
- [x] 构建并发布后端、网页，核对迁移与正式域名。

## 验收

已有邮箱和密码账号继续登录，用户名唯一且不暴露邮箱，用户只能管理自己的身份和会话。失效会话不能执行敏感操作。网站读写均走真实后端，表单失败保留输入。小程序实机验证依赖微信配置与开发工具可用情况，按实际结果报告。


## 实际验证与发布

2026-11-08 完成 107 项自动化测试、类型检查、API 和 Web 生产构建。浏览器完成邮箱注册、原路由返回、首次资料完善、邮箱增删、最后登录方式保护、重新验证、设备撤销及四种宽度检查。补充通过旧密码登录与发帖、回复、点赞、收藏、采纳、Wiki 创建编辑修订记录和关联的回归。

生产后端 example-api、网页 umeet-web-006 均已接管全部流量。正式站完成页面、渠道可用性、权限边界、小程序代理和登录表单检查。认证后的完整账号流程使用本地隔离数据库及注入邮件发送器验证，正式站本轮未进行真实验证码登录后的写入测试。

小程序新增网站账号与微信关联入口，通过构建及 11 页资源检查。其他旧页面仍使用旧接口和独立会话。生产 wechatMini、wechatWeb 均未启用，需要配置微信身份凭据。开发者工具检查未找到可用安装，小程序尚待微信编译、真机验证和上传。

当前规则采用首次确认后固定用户名，昵称允许修改。账号找回、注销与更强的二次验证属于后续阶段。
