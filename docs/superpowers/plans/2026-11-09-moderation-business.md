# 社区管理业务实施计划

目标为已确认的管理业务补齐真实接口和用户入口，沿用 React、NestJS、Kysely 与 MySQL。

- [x] 扩展共享管理契约，新增处罚和申诉表，兼容旧举报。
- [x] 统一举报与证据采集，接入各内容入口、重复限制及举报身份权限。
- [x] 管理动作加入内容处置、警告、封号、能力限制、升级处理及通知。
- [x] 用户管理记录与申诉中心，管理端申诉复核及恢复。
- [x] Wiki 巡查、保护等级和到期、质量、重命名跳转、敏感修订遮蔽。
- [x] 发布、私信、资料、Wiki、旧接口与登录统一执行权限限制。
- [x] 集成测试验证越权、快照、幂等、到期、申诉原子性和历史敏感内容泄露。
- [x] 类型检查、完整测试、构建、本地浏览器验证并清理生成数据。

## 验证记录

完整回归共 35 个测试文件、137 项测试通过，类型检查、前后端构建及差异空白检查通过。新增集成用例覆盖举报快照和匿名、并发去重、每日限额、升级权限、可恢复移除、独立申诉复核、处罚叠加与到期、社区范围隔离，以及 Wiki 隐藏历史与相邻修订副本遮蔽。

本地生产构建浏览器验证覆盖举报、内容修改要求与作者修改、功能限制、申诉、原操作者复核拦截、受限登录申诉和窄屏布局。浏览器验证专用数据已清理。

本轮采用每个账号每日 20 条举报，按上海时区自然日计算。可信 Wiki 编辑用户需注册满 7 天且没有有效处罚。申诉由另一位全站管理员复核，长期处置需在界面明确选择。
