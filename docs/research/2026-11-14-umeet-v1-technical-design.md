# Umeet 综合兴趣社区首版：技术方案

日期：2026-11-14。阶段：技术设计，尚未实施。

需求基线：[已确认的需求访谈稿](./2026-11-14-umeet-v1-requirements-interview.md)。本文中模块划分、表名、接口、参数和实施顺序为工程建议，不把这些建议当成用户逐项指定的要求。

## 1. 基于现有系统做增量扩展

沿用 Next.js 网站、NestJS API、Kysely/MySQL、现有会话与浏览器账号上下文。新增功能继续使用 CommunityApplication 的顶栏、侧栏、通知、头像菜单及移动端导航。

本次读代码确认的接入点：

- `rebuild/apps/web/src/components/community/Pages.tsx`：现有 Discover 展示板块目录。
- `rebuild/apps/web/src/components/community/Application.tsx`：社区页面路由与统一外框。
- `rebuild/apps/web/src/components/community/store.tsx`：订阅、社区状态与操作队列。
- `rebuild/apps/api/src/modules/jobs/`：已有持久化任务、领取租约、续租、重试与失败管理；不等同于已有按业务时间自动入队的完整调度器。
- `rebuild/apps/api/src/app.module.ts`：API 控制器、服务和运行时注册。
- `rebuild/apps/web/src/app/api/backend/[...path]/route.ts`：后端代理目前有路径白名单、层数限制、来源检查、会话转发和约 15 秒请求超时。
- `rebuild/apps/api/src/modules/identity/browser-context.guard.ts`：账号上下文校验，新写接口需要沿用。
- `rebuild/apps/api/src/modules/demo/`：当前网页的部分社区内容及用户状态使用快照接口；新增自动资讯、预测和投票不继续塞入全局 JSON 快照。

新增模块优先独立表和分页 API，避免每次社区刷新都加载全部资讯、证据和投票记录。保留现有内容与 API 的兼容性，不在本轮重写整个社区数据层。

## 2. 页面组织

发现页增加三个页签：板块、资讯、预测。使用 URL 参数保存当前页签与筛选，继续嵌入现有外框。

- 板块：沿用目录，增加 AI、科技、开源、Web3 技术四个板块。
- 资讯：按主题筛选，提供详情、来源链接、收藏、分享、评论。
- 预测：显示今日题目与状态、历史题目列表；详情包含固定的预测、证据、截止与判定规则、评论、关注、核验与复盘。

建议路由形式为 `/#/discover?tab=news`、`/#/discover?tab=forecasts`，详情采用独立 hash 子路由。最终路由字符串由实现时的路由契约测试固定。

资讯和预测不混入普通帖子，不新增首页卡或侧栏入口。页签切换、返回详情和刷新要保留筛选及位置。界面沿用当前语言，帖子和评论使用 Unicode 存储，时间存 UTC，显示时按用户环境格式化；预测业务日始终按 Asia/Shanghai 计算。

## 3. 新板块、兴趣与规则推荐

### 板块与订阅

- 新板块通过独立、幂等的数据初始化创建，避免把它们加入会触发默认订阅的旧默认板块枚举。
- 创建对应 Wiki 空间与公开目录所需的关联，不覆盖同 slug 的既有自定义内容；冲突时进入人工确认。
- 用户首次选择兴趣，可跳过。记录是否完成或跳过引导，以免每次登录重复弹出。
- 不自动加入新板块，不批量改写老用户订阅。保留旧板块及现有历史关联。

### 推荐

新增独立规则推荐读取接口，基于用户主动选择的板块、标签和“不感兴趣”记录产生候选；对可见内容应用质量和时效规则。无兴趣时使用可见的近期优质内容兜底。

先执行权限、屏蔽、下架、删除等过滤，再评分；分页期间使用稳定排序与游标，避免同一页重复。规则按版本记录，并提供结构化理由，如“已订阅开源”“关注的标签”“近期有用讨论”。

点赞、收藏、有效回复等信号做去重和上限处理，限制同作者重复曝光。普通推荐不使用私信、私人草稿或匿名身份关系；不为推断兴趣增加阅读时长画像。服务访问日志与必要的统计目的单独说明。

对当前小规模数据先采用受限候选集加规则排序；不引入向量数据库、额外推荐服务或模型训练。数据量扩大后再检查索引、聚合计数和分页成本。

## 4. 自动资讯

建议新增 `news` 模块，分为来源配置、抓取、规范化、去重、发布和互动六部分。

| 数据对象 | 主要用途 |
|---|---|
| `news_sources` | URL、连接器、主题、是否启用、使用条件核验状态、抓取间隔、ETag 与最近状态 |
| `news_items` | 来源标识、原始 ID、规范化 URL、原标题、来源摘要、发布时间、发现时间、语言、去重键 |
| `news_publications` | 已公开事件卡、主要板块、业务日、聚合条目、版本、公开状态 |
| `news_daily_quotas` | 按板块和上海业务日控制公开卡片不超过 5 张 |
| 互动记录 | 资讯收藏、评论、回复、举报与管理状态 |

这里只存储条款允许保存和展示的内容；来源没有合适摘要时卡片可以没有摘要。AI 增强作为后续可选能力，首版无需依赖它生成资讯正文。

抓取流程：读取到期白名单 → 条件请求 → 严格解析 → 记录发现时间 → 规范化和去重 → 发布前原子领取配额 → 发布卡片。

- 最初按官方 ID 和规范化 URL 精确去重；标题相似与实体时间信息用于可解释的保守聚合。无法确定同一事件时不声称已经可靠合并，可交管理入口处理。
- 一张跨主题事件卡指定一个主要板块并附多个标签，计入主要板块配额，防止重复发布绕过上限。
- 来源一次返回多条内容时按固定顺序处理，超额不跨天无条件补发旧闻；使用发布时间和可配置新鲜度窗口决定仍否适合发布。
- 来源更正作为资讯版本更新，不重新占用一张发布名额；撤回保留内部审计状态。
- 网络请求限制域名、协议、重定向、响应大小、超时和解析规模，拦截访问本机、私有网段及云元数据地址，避免后台抓取成为 SSRF 入口。
- 失败退避，展示最近成功时间与异常状态；使用 HTTP 缓存验证降低带宽与免费额度消耗。

资讯详情里的评论采用独立可审计记录，不伪装成普通帖子。可复用现有交互组件与管理权限，但需要显式接入举报、隐藏、封禁与申诉链路。

## 5. 每日预测与不可覆盖的发布记录

建议新增 `forecasts` 模块。源连接器负责提供证据，题型模板负责定义明确的事件和判定规则，模型负责给出概率和理由；模型不掌握最终结算权限。

| 数据对象 | 主要用途 |
|---|---|
| `forecast_templates` | 领域、题型、可用来源、截止规则、判定规则与启停状态 |
| `forecast_daily_slots` | 上海业务日、计划时刻、运行/暂停状态；业务日唯一 |
| `forecast_questions` | 题目、领域、信息截止、事件截止、时区、例外规则和判定来源 |
| `forecast_evidence` | 来源 URL、发现/获取/发布时间、允许保存的摘录或内容摘要、来源版本 |
| `forecast_runs` | 调用状态、模型与提示版本、输入证据引用、输出、校验结果和用量 |
| `forecast_publications` | 当天公开的固定预测；每日槽位唯一 |
| `forecast_resolutions` | 到期结果、证据、自动/人工来源、待复核与作废原因 |
| 互动记录 | 评论、关注、举报与管理状态 |

### 每天 08:00

1. 轻量调度器按数据库中的下次到期时刻幂等创建当天任务；多实例使用唯一键和事务避免重复入队。
2. 在已有可用来源的领域中选择一题。领域不要求每日轮流或数量均等，未准备好的领域显示状态。
3. 验证题目仍指向未知的未来结果，固定问题、截止时间、判定来源、例外与证据的信息截止时点。
4. 收集可用证据并调用允许的免费模型适配器，校验概率范围、结构、引用和定义一致性。
5. 事务发布一条固定预测。模型调用和网络请求在数据库事务外执行。
6. 无合格题目、额度耗尽、来源异常或模型不可用时，记录当天暂停原因；不复用旧题冒充新题，不用随机数字填充。

每天的一条是全站一题，不是每个领域一题。发布后固定概率、理由和原始证据引用，后续只能追加结果、复盘及明确的纠错说明。题目严重错误时允许作废并留档，不能原地改成更容易成功的预测。

调度实现不能假设云托管实例永远在线。先核验实例最小数量、空闲行为和既有触发能力；在没有免费可靠唤醒能力时，不承诺 08:00 的生产准点性。进程重启后记录错过的业务日并支持受控恢复，同一天仍最多一条公开预测。是否允许当天迟发应在运行策略中明确展示，不能伪装为准点发布。

### 到期核验

为每个题型提供明确判定适配器。官方结构化数据符合预定规则时自动结算；来源矛盾、认证尚未完成、赛事取消、文件含义不明等进入待复核。

结果状态与预测发布状态分开。等待人工处理不会触发新的概率生成。管理员确认、作废和纠错均保留审计、证据与操作者；公开页面区分已发生、待官方确认、待人工复核及已作废。

### 评价

二元题使用 Brier 分数，在已明确结算的题上计算，并列出题数、领域、提前量、未结算及作废数。发布概率只有一版，因此每题只计一次。试运营不把少量题目的短期分数当成能力承诺，也不回填事后已知结果的“历史预测”。

## 6. 普通帖投票与每周讨论题

使用独立投票表而非全局社区快照：`polls`、`poll_options`、`poll_votes`，与当前网页实际使用的帖子标识建立明确关系，避免误接到另一套讨论帖子表。

- 只支持单选；注册账号投票，数据库唯一约束 `(poll_id, user_id)`。
- 普通用户接口只返回汇总，不返回投票者与选项对应关系。后端保留验证一人一票所需的关联，不能将此描述成系统也无法识别的完全匿名。
- 题目/选项编辑与首次投票在同一投票行上串行校验，保证不能在有人投票后并发改题。
- 以服务器时间判断截止，截止后停止投票；汇总和并发写入须一致。
- 纠错通过追加说明或撤销、重开处理；撤销不删除既有结果。
- 每周讨论题由运营者使用普通发帖和投票能力人工发起，不增加新的 AI 或定时自动发帖流程。

是否允许截止前改选不是已确认需求；工程实现建议将同一账号的选择更新视为一条有效票，并在交互上明确当前选择。如需采用禁止改选策略，应在实现前固定并测试这一行为，不改变已确认的一人一票原则。

## 7. API、权限与治理

建议新增 `/api/v1/news`、`/api/v1/forecasts`、`/api/v1/polls`、`/api/v1/recommendations` 等模块。具体 URI 在契约设计时固定；浏览器通过现有 Next.js 代理访问，扩展严格路径白名单，不能为接入新模块而取消路径检查。

读取接口分别分页。收藏、评论、关注、投票、不感兴趣等写操作沿用会话、来源、账号上下文校验与幂等要求。用户发起长任务时只提交短请求并读取任务状态，不让模型生成占用 15 秒同步代理窗口。

后台增加来源状态、领域开关、模型额度、每日发布槽位、暂停原因与待核验队列。新内容类型要扩展现有举报目标、可见性处理和审计类型，而不只添加前端“举报”按钮。

一般内容即时展示的选择不排除注册要求、频率限制、广告链接约束和账号处罚。限流、举报响应与异议处理沿用统一权限边界。受限用户不能借资讯评论或预测评论绕过社区处罚。

## 8. 零新增付费与运行隔离

首版复用已有数据库和服务。先核验真实部署资源；本地模型、自建向量检索、额外容器、付费数据源和付费检索 API 均不作为默认依赖。

免费模型接入要求确认正式使用条件、数据处理方式、可达性和账户是否可能自动计费；未确认的提供商默认关闭。日请求/用量预算在外部调用前预留，并发受限，收到限流或额度耗尽后暂停；不静默切换付费模型。

已有任务处理器并发与领取策略需要检查。若长模型任务会阻塞其他业务，按任务类型分组领取并给预测处理器限制一个并发；可以在既有服务中实现，不先新增部署服务。处理器应支持取消、超时和租约丢失终止。

重试不等于外部调用恰好一次。若模型 API 不支持幂等键，必须记录调用中的不确定状态，对网络超时后的重试设独立预算，不承诺绝不重复消耗免费额度。公开发布通过业务日唯一约束实现至多一次。

正常网页访问、消息与已有任务优先于可选推理。来源采集和核验使用缓存、条件请求、小批次、退避及明确的抓取上限。

## 9. 验证重点与分批实施

| 批次 | 内容 | 核心验收 |
|---|---|---|
| A | 数据契约、新板块、兴趣选择、发现页分区 | 老数据不丢，新板块不自动订阅；同一网站外框；多语言文本可用 |
| B | 普通帖投票、规则推荐与负反馈 | 一人一票并发约束、截止与冻结；不泄露个人票；屏蔽内容不进入推荐 |
| C | 白名单资讯、去重、配额、收藏评论和管理接入 | 多实例发布也不超过每板块每日 5 条；重复/撤回/来源故障可正确处理 |
| D | 预测槽位、来源/题型、免费模型适配、冻结发布 | 同一天最多一题；暂停不造假；发布后概率和理由不变；零付费降级 |
| E | 到期核验、人工复核、复盘与试运营观测 | 自动和人工结果有证据；争议不强行结算；全量历史可追溯 |

每批在本地独立测试数据库验证，再按明确发布流程准备迁移。重点测试跨账号操作、重复任务、崩溃恢复、时区切换、并发配额、投票编辑竞态、模型超时和额度用尽。UI 验证涵盖资讯与预测详情返回、原有发帖/Wiki/消息、窄屏和长外文文本。

试运营记录真实讨论、回访、收藏与订阅、来源失败/重复率、每日预测成功/暂停率、待复核数量和人工处理耗时。先建立基线，再选择量化增长目标；不通过系统自动生成评论或假互动填充指标。

## 10. 进入开发前仍需完成的事实核验

- 实际云托管资源、常驻/休眠行为和已有免费触发能力。
- 每个首批资讯源与预测判定源的接口、展示授权、速率限制与可达性。
- 至少一个满足正式使用条件、无自动付费回退的模型接入，或可验证足以运行的既有本地算力。
- 面向境内外公开服务及各类资讯、生成内容的适用条件。
- 已有代码中两套帖子接口与实际用户入口的衔接，扩展投票及管理对象时以实际运行路径为准。

这些事实不改变已确认的零付费和异常可暂停原则。未核验的领域或 AI 接入以关闭/暂停状态呈现；技术方案不承诺所有领域从第一天有题、免费额度永久存在或服务器准点能力已经具备。
