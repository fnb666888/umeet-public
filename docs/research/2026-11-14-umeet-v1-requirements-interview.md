# Umeet 综合兴趣社区：首版需求访谈整理稿

日期：2026-11-14。状态：用户已确认需求及投票默认规则。

本文整理本轮交互式访谈的 35 项回答，并经用户明确确认。它是首版需求基线，不代表技术可行性已经完成验证或功能已经实现。功能实现与上线另行开展。

## 一、产品与运营

- 讨论与知识为主体，每日自动预测为特色。
- 第一阶段聚焦 AI、科技、开源和 Web3 技术话题。
- 直接公开开放，边推广边积累用户。
- 同时面向境内外用户；这不自动等于境内外双区部署。
- 允许多语言发帖，首版不建设界面翻译或内容翻译。
- 一般内容即时展示，以举报和事后处理为主；不将首帖人工预审设为普遍前置条件。
- 用户每周可投入约 4–8 小时进行运营与异常复核。
- 新增付费预算为零。免费优先，资源不足可缩减或延期 AI 功能；零新增付费不代表既有服务器没有资源消耗。
- 首轮重点验证真人持续讨论、回访，以及自动资讯和预测的可维护性。

## 二、板块、兴趣与推荐

- 新增 AI、科技、开源和 Web3 技术兴趣板块，保留现有板块及历史内容。
- 新板块不自动订阅；首次提供兴趣选择，可以跳过。
- 不批量改变已有用户的订阅。原有板块的历史订阅不因为新增主题而被清空。
- 保留最新、热门和关注等现有浏览能力。
- 新推荐采用兴趣标签、内容质量和时间等规则排序，展示推荐理由。
- 兴趣主要来自主动订阅和主动选择的标签，并提供“不感兴趣”。
- 首版不引入基于阅读行为训练的复杂个性化推荐模型。

## 三、自动资讯

- 只进入发现页的独立资讯专区，暂不混入普通帖子。
- 从预先确认的来源白名单中采集；来源有更新即处理。
- 每个板块每天最多 5 张资讯卡；重复报道合并，不凑满数量。
- 最低内容为原标题、来源、链接及来源自带摘要；无合适摘要时不编造摘要。
- 有可用 AI 时可增强，但 AI 不作为资讯正常展示的必需条件，也不挤占预测优先资源。
- 支持收藏、分享、评论；评论保留在资讯详情中。
- 来源接入需核验接口、使用条款、可展示内容、抓取限制和适用的运营要求，不能仅凭公开 RSS/API 自动批准。

## 四、每日预测

- 只进入发现页的独立预测专区；首版不在首页放每日预测卡，不新增独立侧栏导航。
- 每天北京时间 08:00 发布一道新的预测题，境外用户同时看到对应当地时间。
- 每题的概率和理由发布后固定，不进行后续概率更新。
- 到期增加结果核验和复盘记录；保留原始预测，不将事后核验视为改写原预测。
- 首版计划覆盖政治、经济、科技、比赛等多领域。
- 各领域按已核实的免费来源准备情况开放；未准备好的领域暂不出题，页面明确说明状态。
- 主要选择 1–30 天内可以核验的问题，允许少量长期题。
- 自动选题和发布限制在预设题型及来源内；异常、证据不足、免费额度耗尽等情况下允许暂停，不强行补出一个概率。
- 预测要展示问题、概率、理由、证据来源、信息截止时刻、题目截止时刻及判定规则。
- 到期按预定来源自动核验；来源冲突或含糊时由用户复核。
- 用户可以阅读、评论、关注预测与复盘；首版不提供个人提交概率、预测积分或排行榜。
- 完整保留题目、原始预测、证据和结果状态，包括失败、暂停、待核验及作废记录。

## 五、AI 与 Web3

- 首版生成式 AI 优先且只用于每日预测与证据整理。
- 社区问答、长帖摘要、写作辅助、Wiki 草稿辅助、翻译等后续再做。
- 可以使用允许正式服务使用的外部免费 AI 额度，只发送适合且获准发送的内容；额度耗尽即暂停，不自动转入付费。
- 是否能由现有服务器承担本地推理，仍需实际资源核验；不能以项目里存在定时任务推断本地模型已可运行。
- Web3 首版为技术内容、事件讨论和可验证记录研究。
- 先保存完整预测记录与证据；签名导出、外部时间戳、链上存证留待后续研究。
- 钱包登录、链上身份、代币激励、充值下注和交易机制不在本轮首版范围内。

## 六、投票与每周讨论题

已确认范围：普通帖子增加投票能力，由用户作为运营者发起每周讨论题。

以下默认规则已随本文经用户明确确认：

- 首版先支持单选投票；多选和复杂问卷后续再考虑。
- 注册账号可以投票，每个账号每个投票保留一个选择。
- 普通用户看到汇总结果，不公开投票者与选项的对应名单。
- 发起者设置截止时间；截止后停止投票并保留结果。
- 有人投票后冻结问题与选项，必要纠错通过追加说明或撤销并重新发起处理，保留记录。
- 每周讨论题由运营者人工发起，不新增自动生成讨论题的 AI 任务。

## 七、保持现有体验

- 延续社区统一的顶栏、侧栏、账号菜单与页面布局。
- 资讯、预测作为发现页内的功能区；不为每项能力再搭建一套网站外框。
- Wiki 保留统一入口；此次访谈不增加新的通用聊天入口。
- 原有帖子、Wiki、账号、订阅、消息与管理记录保留。

## 八、事实核查与后续工程条件

这部分是技术核查发现或待验证条件，不是让用户猜测技术参数：

1. 仓库描述了微信云托管 API 与网站两个服务，但生产 CPU、内存、磁盘、剩余额度和实际负载尚未确认；未发现已接入模型推理运行时的充分证据。
2. 已有 MySQL 异步任务、租约、重试和失败管理基础，可作为每日任务的复用起点。
3. GitHub 发布信息、官方机构文件与经济数据等有候选接入方式；覆盖范围、权限和来源条款须逐项验证。
4. 目前未确认同时具备充分覆盖、可靠性和免费正式使用条件的通用体育来源，不能承诺每个领域从第一天都有题。
5. 尚未最终选定免费 AI 提供商或具体模型，不承诺长期免费额度、固定预测质量或生产可达性。
6. 正式公开范围须核对境内外服务、外部资讯、个人信息、生成内容标识等适用要求；功能选择不等于完成相关核验。
7. 首轮先收集回访、真实讨论、资讯去重、任务成功/暂停、核验与人工维护耗时等指标，数值增长目标在有基线后制定。

用户已确认需求理解；后续据此制定技术方案、拆分实施步骤和验证可行性。
