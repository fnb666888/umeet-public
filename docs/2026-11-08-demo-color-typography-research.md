# Umeet demo 配色与字体调研

调研日期：2026-11-08。对象：demo/web-ux。本次只调研、审阅代码和观察实际页面，没有修改 demo。候选方案不代表已确定的品牌设计。

## 结论

当前更需要统一颜色职责、字体回退和文字层级。现有颜色已经接近 X 的经典浅色界面；仅更换主色或英文字体，改善可能有限。建议先整理排版，再用同一份真实中文页面比较主色。优先推荐清爽蓝色，第二候选为校园绿色。

## 调研范围与限制

阅读了 index.html、css/style.css、示例内容，并在本机 Chrome 打开首页。打开 Discourse Meta、X 官方品牌页和未登录入口、Reddit 官方品牌页，以及下述工具和设计规范。Reddit 社区首页出现人机验证，未继续处理；X 没有登录观察信息流。因此品牌资料、历史产品风格和本次实测分开描述。

CSS font-family 表示候选字体，不等于每个汉字都由第一项绘制。本机 demo 另外读取了浏览器实际字体信息，中文帖子标题使用 Microsoft YaHei UI。

## 三个社区的做法

| 社区 | 配色与结构 | 字体证据 | 借鉴点 |
| --- | --- | --- | --- |
| Discourse | 可定制主题。当前 Meta Branded 使用白色内容面板、紫色强调和淡紫色背景，分类另有小面积颜色 | 本次变量 primary 为 #333638，secondary 为 #ffffff，tertiary 为 #7b5fe2；声明 Inter, Arial, sans-serif；抽样话题标题约 18.38px、400 | 最接近长期讨论与 Wiki 场景。学习话题、分类、元信息层次；不能把这个定制主题当成所有 Discourse 的默认方案 |
| X | 黑白构成品牌主体；经典产品界面以蓝色表达链接和选中状态，内容、头像和文字提供重点 | 本次未登录入口实测字体栈以 TwitterChirp 开头，后接系统字体 | 学习克制的强调色和明确主次。demo 已经接近经典 X 色值；另换一组相似蓝色收益有限 |
| Reddit | 官方品牌明确 OrangeRed #FF4500；品牌标识色不等于整套产品 UI 色板 | 官方介绍 Reddit Sans 的大 x-height、易区分字形及阅读效率；Google Fonts 有对应字体页面 | 学习品牌识别与内容可读性的结合；不要把所有链接、按钮、分类都染成品牌橙红 |

Discourse Meta 也说明，400 字重的标题本身并没有问题，字号、间距、行宽和周围信息的重量共同决定效果。

## demo 的具体问题

1. **颜色职责需要明确。** 主要文字 #0f1419、说明文字 #536471、交互深蓝 #0b6ea9、强调亮蓝 #1d9bf0。主按钮为黑色，选中导航多为灰底深字，解决状态为绿色。黑按钮配蓝链接本身成立，重点是主操作和选中状态是否足够明确。变量 moss、leaf 已经不再对应实际蓝色和灰色，建议逐步改为 action、surface、text-secondary 等用途名称。
2. **辅助信息有时比主内容更重。** 紧凑列表标题 16px / 400 / 1.45；作者名 600；右栏小标题 750；部分导航、标签使用 650、700、750。可比较“标题增大到 17–18px、保留 400”和“标题 16–17px、500/600”两种调整，同时降低作者和辅助信息的重量。
3. **写了字体名不等于加载字体。** 当前栈是 Segoe UI、PingFang SC、Microsoft YaHei UI、Microsoft YaHei、Noto Sans SC、sans-serif。项目没有加载对应外部字体文件。本机中文标题实际使用 Microsoft YaHei UI，其他设备会不同。只换 Inter、Chirp 或 Reddit Sans，对大量中文主体字形帮助有限。
4. **字重和字号过于零散。** 650、750 等 CSS 数值合法，但静态字体可能映射到临近字重或合成显示。先收敛到 400、500/600、700 三档，以及少量字号角色，再按实际字体检查。

## 字体路线

| 路线 | 方式 | 优点 | 代价与阶段 |
| --- | --- | --- | --- |
| 系统字体，建议先试 | system-ui 加明确中文和 Emoji 回退；先整理尺寸、字重 | 快、符合设备阅读习惯、成本低 | 跨平台字形不完全一致，适合当前 demo |
| 固定中文字体 | 真正加载 Noto Sans SC 等授权清晰的中文字体，必要时搭配 Inter 或 Reddit Sans | 中文字形和字重可控 | 需要分片或子集、WOFF2、font-display 和网络验证；适合视觉方向确定后 |

建议的比较基线，未应用到页面：

| 用途 | 字号 / 行高 | 字重 |
| --- | --- | --- |
| 页面标题 | 24px / 32px | 600 或 700 |
| 列表标题 | 17px / 26px | 500 或 600，按实际字体比较 |
| 详情正文 | 16px / 28px | 400 |
| 导航、按钮 | 14–15px / 22px | 常态 400/500，选中 600 |
| 作者、时间、回复数 | 13px / 20px | 400，必要信息才强调 |

中文长文先以每行约 35–45 个汉字试读；手机正文优先保持 16px 左右。Ant Design 的系统字体与层级方法值得参考，但它面向中后台，其 14px 默认正文不应直接当成社区长文答案。

## 三个候选颜色方向

以下是本次提出的候选种子色，并非任何平台的官方方案，也不是完整组件状态表。

共用：白色内容面 #ffffff、次级表面 #f6f7f9、主要文字 #1f2328、次要文字 #636b74、普通分隔线 #e3e6ea。分隔线不能直接作为所有输入框或焦点的唯一可识别边界。

| 方向 | 操作与链接 | 选中浅底 | 气质与适用性 |
| --- | --- | --- | --- |
| A 清爽蓝色，优先推荐 | #3568d4 | #edf3ff | 清晰开放，适合广场、问答和 Wiki，与现有设计连续性最好 |
| B 校园绿色 | #28634e | #edf5f0 | 安静、互助和校园生活；需区分品牌绿与已解决状态绿 |
| C 活跃橙红 | #b5472b | #fff0ea | 适合活动、交易与即时互动；需控制面积并与错误状态区分 |

三者都以中性色为主体。分类色用于图标、小标记或少量标签，不给每条帖子铺不同颜色；分类和状态同时保留文字或图形标识。

## 对比度

按 WCAG 相对亮度公式计算，不透明 sRGB，四舍五入。不是完整无障碍审计。

| 前景 / 背景 | 对比度 | 含义 |
| --- | --- | --- |
| 现有 #536471 / 白色 | 6.12:1 | 满足普通文字 AA |
| 现有 #0b6ea9 / 白色 | 5.50:1 | 满足普通文字 AA |
| 现有 #1d9bf0 / 白色 | 约 3.00:1 | 不满足普通小文字 4.5:1，适合非正文强调；当前选中下划线用途不等于小字存在问题 |
| 候选 #3568d4 / 白色 | 5.14:1 | 可用于普通链接，也可与白色按钮字搭配 |
| 候选 #28634e / 白色 | 7.04:1 | 满足普通文字 AAA |
| 候选 #b5472b / 白色 | 5.38:1 | 满足普通文字 AA |

透明、悬停、换底色后需要重新检查。现有灰色和深蓝色本身并不缺乏对比度，页面显得平的原因应更多从层级与信息密度排查。

## 可以直接帮助你的网上方案

| 资源 | 解决什么 | 用法 |
| --- | --- | --- |
| Radix Colors，最推荐 | 12 阶颜色对应背景、交互、边框、实色、文字；支持明暗与自定义色板 | 中性灰加一个主色，映射到现有 CSS 变量；无需引入 Radix 组件或重写项目 |
| Realtime Colors | 在网页示例中即时预览颜色和字体，可导出 | 快速排除不协调组合，再放回中文帖子页验证；英文营销页不能代替真实信息流 |
| Ant Design 字体规范 | 系统字体栈、字阶、行高、字重、文字色 | 借规则，避免直接套整套中后台外观 |
| Google Fonts：Noto Sans SC、Reddit Sans | 字体发现与预览入口 | 用真实中文和中英混排样句比较；Reddit Sans 主要作为拉丁字体选择 |
| WebAIM Contrast Checker | 检查具体前景背景对比度 | 校验链接、按钮、说明文字和选中背景；美感仍需页面比较 |

推荐组合：Radix 负责颜色状态，系统字体或实际加载的 Noto Sans SC 负责文字，真实 demo 负责视觉验证。随机生成五个色块很难解决目前的主次问题。

## 后续比较方法

同一份首页和详情页比较 A、B 主色，保持内容、布局和排版一致。再比较整理后的系统字体与实际加载的 Noto Sans SC，避免同时更换全部因素而无法判断改善来源。

观察：第一眼能否看到帖子标题；作者、标签、热榜是否压过主内容；长文是否容易连续阅读；选中与主操作是否明确；Windows、手机和实际网络是否稳定。
