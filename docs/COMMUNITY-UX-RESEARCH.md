# 社区交互设计调研：Discourse / Reddit / X 与 Umeet Web 端改造方案

> 调研日期：2026-11-07 · 范围：Web 端（`rebuild/apps/web`，Next.js）发帖、回复、Wiki 交互
> 结论先行：问题不是缺功能，而是**入口隐藏太深、列表没有导向性、回复没有层级感、Wiki 只有"目录"没有"导览"**。三大主流社区都在这四件事上做了大量细节设计。

---

## 1. 一页结论（TL;DR）

| 问题 | 主流社区的做法 | 我们要做的 |
| --- | --- | --- |
| 发帖入口藏在 `<details>` 折叠里，"找半天不知道点哪" | Reddit：信息流顶部常驻大按钮 + 移动端中央 FAB；Discourse：顶部 `+ New Topic` 常驻 | 社区页顶部常驻高亮"发帖"按钮，登录后全站可见 |
| 信息流只有"最新"一种排法，卡片没有投票/热度信号 | Reddit：默认 Best（热度）+ Top/New 切换；Discourse：Latest/Top/Categories 页签 | 信息流增加 最新/热门 切换，卡片右下加投票数与回复数 |
| 回复是一层平铺，"回复某人"藏在 `<details>` 里，上下文丢失 | Reddit：嵌套缩进树 + 可折叠；Discourse：引用块 + "回复线" | 评论树两级缩进显示，回复时输入框上方出现引用条，不再折叠表单 |
| Wiki 只有标题列表，无目录/更新时间/贡献者，读者不知道"里面有什么" | Wikipedia/Wikis：TOC + 索引页含摘要 | Wiki 首页改成目录卡片（标题+摘要+最近更新+字数），文章页加 TOC 与"编辑/历史/讨论"三入口 |

---

## 2. 现状诊断（基于代码的逐条问题）

以下问题全部来自 `rebuild/apps/web` 现有实现：

### 2.1 全局导航（`AppShell.tsx`）
- 左侧栏有"首页 / 发现社区 / 我的记录 / 共建 Wiki"四个链接，但**没有任何"发帖"入口**——发帖只能先进某个社区再展开折叠框。
- 顶部搜索框 `action="/search"`，但 `app/search/page.tsx` **不存在**，搜索点了必然 404。
- 移动端用 `<details>浏览社区` 折叠导航，收起后整站只剩顶栏，移动端可用性差。

### 2.2 首页与信息流（`page.tsx` + `DiscussionFeed.tsx`）
- 首页 heading 是"首页 / 所有社区的公开帖子，按最新发布排列"——**没有情绪、没有分类、没有热度**，只是一个数据库视图。
- 卡片信息：社区名/作者/时间、标题、全文摘要、`得分 X · N 条回复`。没有投票交互、没有标签、没有图片。
- 分页只有"下一页"游标链接，回退只有"返回最新"，没有无限滚动或页码。
- 右栏"找到你的社区"只有名称+描述，没有帖子数/在线感/最新动态，无法比较哪个社区活跃。

### 2.3 社区页（`c/[slug]/page.tsx`）
- 发帖表单放在 `<details>在这个社区发帖` 里，**默认收起**——这是"找不到该点哪里"的最大来源。
- 社区导航是纯文字链接"讨论 / 共建 Wiki / 举报处理"（举报处理这个管理员功能不该出现在普通用户导航里）。
- feed-bar 写死"社区帖子 / 最新"，与首页一样没有排序切换。

### 2.4 帖子详情（`posts/[id]/page.tsx`）
- 评论表单在**评论区顶部**，回复某条评论的表单藏在每条评论的 `<details>回复 author` 里——输入框位置不固定，用户来回找。
- 回复用 `discussion-reply` div 包裹，**只有一层缩进**，没有回复线、没有头像列、没有折叠；回复也不显示"回复了谁"的引用。
- 评论本身**没有点赞**，只有帖子有投票；评论区没有排序。
- 举报用 `<details>举报帖子`，和正文挤在一起，视觉权重过高。

### 2.5 Wiki（`c/[slug]/wiki/*` + `wiki/[id]/*`）
- Wiki 首页是**纯标题列表**（标题 + "查看词条与修订历史"），没有摘要、没有最近更新时间、没有字数/贡献者、没有搜索和分组——读者完全无法判断内容。
- 文章页：Markdown 渲染 + wikilinks 已可用，但没有 TOC（长文不可导航）、没有面包屑、没有"编辑/历史/讨论"工具栏、没有最近编辑者信息。
- 新建词条入口是一个孤立的主按钮，位置游离于阅读流程之外。
- 编辑冲突已有 `ConflictResolver`，这是好底子，但用户侧缺少"正在被谁编辑"的协作提示。

## 3. 基准研究：三个主流社区怎么做的

### 3.1 Reddit —— 「投票驱动的信息流 + 嵌套评论树」

**页面骨架（桌面）**
```
┌──────────────────────────────────────────────────────┐
│ 顶栏: Logo | 搜索框(大而居中) | 发帖按钮 | 收件箱 | 头像 │
├──────────────┬───────────────────────────────────────┤
│ 左: 社区列表  │  Feed Tab: [Best] [Hot] [New] [Top]    │
│ (我的社区+    │  ┌──┬────────────────────────────┐     │
│  发现/排行榜) │  │▲ │ r/xxx · 发布者 · 时间       │     │
│              │  │42│ 标题(大字)                  │     │
│              │  │▼ │ 正文预览 / 图片             │     │
│              │  │  │ 💬 N评论  ↗分享  ⚑保存      │     │
│              │  └──┴────────────────────────────┘     │
│              │  右栏: 社区信息卡 / 社区规则 / 发帖按钮   │
└──────────────┴───────────────────────────────────────┘
```

**关键交互细节**
1. **投票列常驻卡片左侧**（▲ 分数 ▼），扫一眼就知道哪条内容值得点开——这是 Reddit 信息流的"导向性"来源。
2. **发帖按钮永远三处可见**：顶栏"Create Post"、社区页右栏"Create Post"、移动端底部中央 `+`。点开社区页时按钮自动携带该社区。
3. **发帖是类型先行**：进入后先选 Tab（Text / Link / Image / Poll），表单随类型变化。
4. **评论树**：每层缩进 + 左侧细竖线（回复线），超过阈值可"continue this thread"；每条评论有自己的 ▲▼ 分数；`[–]` 一键折叠整个子线程；"sort by best/top/new" 对评论也生效。
5. **OP 徽标**：楼主在评论区显示蓝色 "OP" 徽标，一眼识别。

### 3.2 Discourse —— 「论坛式列表 + 引用回复 + 电梯时间线」

**页面骨架（桌面）**
```
┌──────────────────────────────────────────────────────┐
│ 顶栏: Logo | 分类/最新/热门/未读 页签 | 搜索 | + 新话题  │
├──────────────────────────────────┬───────────────────┤
│ 话题列表(表格):                   │ 右栏:              │
│ 标题 + 分类徽章 + 标签            │  社区横幅(banner)   │
│      发布者头像列(前5位参与人)     │  分类说明卡         │
│      回复数/浏览数/活跃时间 列对齐  │  相关话题           │
└──────────────────────────────────┴───────────────────┘
```

**关键交互细节**
1. **列表是"表格"不是"卡片"**：标题占主要宽度，头像列直观显示"谁在讨论"，右端三个数字列（回复/浏览/活跃）严格对齐——信息密度高但极有导向性。
2. **新话题按钮在顶栏常驻**，键盘 `c` 快捷键直达；composer **固定在视口底部**，带实时 Markdown 预览和字数提示，编辑中永不丢失。
3. **引用回复**：点"回复"时自动把原帖压成 `引用块` 放进 composer；发出去后正文里显示灰色引用条 + 头像 + 名字，点击引用块可滚动到原楼层。楼中楼用"↩ 回复线 + 参与者折叠条（如 '↩ 3 more replies'）"压缩层级。
4. **话题内时间线**：右侧滚动条显示"当前楼层 / 总楼层"，可拖动跳楼，底部有"回复此话题"悬浮条。
5. **Wiki Post（Discourse 原生概念）**：第一帖可标记为 wiki——**任何登录用户都能编辑**，每次编辑记入修订历史；帖子显示最后编辑者与时间。这正是"共建知识"的最轻实现。
6. **Solved 勾选**：问答类话题，楼主可把某条回复勾为"已解决"，列表标题前出现 ✅。

### 3.3 X (Twitter) —— 「单列时间流 + 会话式回复线 + 互动条」

**页面骨架**
```
┌────────────────────────────┬───────────────────────┐
│ 顶栏: Logo  首页 通知  搜索  │ 右栏: 搜索 / 热门趋势   │
│ ────────────────────────── │  / 推荐关注            │
│ [时间线] 单列卡片            │                       │
│   头像 名字 @id · 时间      │                       │
│   正文                      │                       │
│   💬回复 🔁转发 ♡喜欢 📊浏览 │                       │
│ [详情页] 同一条帖子的会话树   │                       │
│   父帖 → 连接竖线 → 逐层回复 │                       │
└────────────────────────────┴───────────────────────┘
```

**关键交互细节**
1. **互动条是四宫格图标**（回复/转发/点赞/浏览），数字灰色小字——点赞成本极低，信息流因此极活跃。
2. **详情页 = 会话页**：从任何一条回复点进来，页面按"父帖在上、回复按对话线向下展开"重排，上下文永不丢失。
3. **回复折叠**：低质量回复收进"显示更多回复"，主干保持干净。
4. **通知聚合**：'A、B 和另外 12 人赞了你的帖子'——避免通知爆炸，Web 端顶栏铃铛带未读数。
5. **发帖入口**：顶栏左侧常驻蓝色大按钮（桌面）/ 右下 FAB（移动），任何页面一键弹出 composer。

### 3.4 三者对比与我们各取什么

| 维度 | Reddit | Discourse | X | Umeet 取舍 |
| --- | --- | --- | --- | --- |
| 信息流排序 | Best/Hot/New | Latest/Top/Unread | 算法流 | 最新 + 热门（按投票/回复衰减分） |
| 列表形态 | 卡片+票列 | 表格+头像列 | 单列卡片 | 卡片 + 右下互动数据（保留现有卡片风格） |
| 发帖入口 | 顶栏+右栏+FAB | 顶栏 + 键盘快捷键 | 顶栏 + FAB | 顶栏常驻 + 社区页高亮按钮 |
| 评论结构 | 嵌套树+折叠 | 引用块+回复线 | 会话线 | **两级缩进树 + 引用条**（不做无限层） |
| 回复输入 | 点击评论下方内联 | 底部固定 composer+预览 | 底部输入条 | 底部固定输入条 + 选中评论出现引用条 |
| Wiki | — | Wiki Post（人人可编辑） | — | 独立 Wiki 保留，**索引页做成目录卡 + TOC** |
| 已解决标记 | — | Solved ✅ | — | 问答/求助帖支持标记最优回复 |
| 通知 | 收件箱 | 顶栏铃铛 | 聚合通知 | 顶栏铃铛 + 聚合 |

## 4. 改造方案（按页面）

### 4.1 全局导航（`AppShell.tsx`）
```
┌──────────────────────────────────────────────────────────────┐
│ u/umeet | [搜索框: 帖子/Wiki/社区]              [+发帖] 🔔 头像 │
├──────────┬───────────────────────────────────┬───────────────┤
│ 首页      │ 主内容区                           │ 右栏(桌面):    │
│ 发现      │                                   │ · 社区活跃榜   │
│ 我的记录  │                                   │ · 今日热门     │
│ 共建Wiki  │                                   │ · 侧栏广告位   │
│ ──────   │                                   │  (暂可留空)    │
│ 我的社区   │                                   │               │
│ ·树洞     │                                   │               │
│ ·交易     │                                   │               │
│ ...      │                                   │               │
└──────────┴───────────────────────────────────┴───────────────┘
```
改动：
1. 顶栏加 **[+ 发帖]** 主按钮（登录跳 `/communities` 选社区；已在社区页则预选该社区）；未登录点开登录。
2. 补齐 `/search` 路由页（先做帖子标题+Wiki 词条 like 查询即可），否则移除搜索框。
3. 顶栏加 🔔 通知入口（先复用现有通知数据，做未读红点即可）。
4. 左侧"我的社区"列表补活跃信号：`社区名 · 今日 N 帖`。

### 4.2 首页信息流（`page.tsx` + `DiscussionFeed.tsx`）
```
┌ 主内容区 ────────────────────────────────────┐
│ [🔥 热门] [🕒 最新] [📌 置顶公告条(可关)]       │
│ ┌──────────────────────────────────────────┐ │
│ │ r/校园日常 · 同学A · 3小时前               │ │
│ │ 【求助】图书馆哪层插座最多？                │ │
│ │ 正文预览两行……                            │ │
│ │ ▲ 12   💬 8 回复   📚 引用Wiki×2           │ │
│ └──────────────────────────────────────────┘ │
│ …卡片…  [无限滚动，底部显示"已到底"           │
└──────────────────────────────────────────────┘
```
改动：
1. feed-bar 改成**页签切换**：热门（默认）/最新。热门排序 `score - 降价因子×小时数`，服务端加一个 `?sort=hot` 即可。
2. 卡片尾部互动数据加 hover 可点（点赞直接在列表内完成，不需要进详情）。
3. 分页从"下一页"链接改为**无限滚动 + 底部哨兵**（保留游标参数不变，仅改触发方式）。
4. 空态加引导："还没有帖子，成为第一个分享的人 →"（带发帖按钮）。

### 4.3 社区页（`c/[slug]/page.tsx`）
1. **`<details>` 折叠发帖框删除**，改为顶部常驻高亮按钮 **「+ 在此发帖」**（未登录时按钮触发登录）。理由：Reddit/Discourse 的发帖入口从不折叠。
2. 社区导航改为页签式：`讨论 | Wiki | 关于`，"举报处理"移出普通导航（仅管理员侧栏可见）。
3. 社区头加活跃统计：`成员 N · 今日新帖 M · Wiki 词条 K`。
4. 树洞社区保留匿名提示，但移到发帖表单内 inline 提示，不占社区首页。

### 4.4 帖子详情 / 回复（`posts/[id]/page.tsx`）★重点
```
┌ 帖子正文（含投票、分享、举报折叠成 ⚑ 小图标）────────┐
├────────────────────────────────────────────────┤
│ 回复 · 8     [最热] [最新]                        │
│ ┌ 评论卡 ────────────────────────────────┐      │
│ │ A · 2小时前                    ▲3      │      │
│ │ 内容……                          💬回复 ⚑ │      │
│ │ │ ┌ 回复(缩进+左竖线) ──────────────┐    │      │
│ │ │ │ 楼主B · 1小时前        [楼主]   │    │      │
│ │ │ │ 引用 @A：哪层插座多？           │    │      │
│ │ │ │ 二楼大开间……            💬回复  │    │      │
│ │ │ └────────────────────────────────┘   │      │
│ │ [↩ 展开 2 条更多回复]                    │      │
│ └────────────────────────────────────────┘      │
├────────────────────────────────────────────────┤
│ 💬 底部固定输入条:                                │
│ ┌──────────────────────────────────────────────┐│
│ │ ↩ 正在回复 A："哪层插座多？"            [×]    ││ ← 引用条(选中时出现)
│ │ [输入回复…]                        [发送]     ││
│ └──────────────────────────────────────────────┘│
└────────────────────────────────────────────────┘
```
交互规则（对应"回复"的步骤设计）：
1. **点任意评论的"回复"→ 底部输入条**浮出引用条"↩ 正在回复 A：内容前 30 字…"，可点 × 取消。不再把表单嵌进 `<details>`。
2. 评论渲染为**两级树**：一级评论平铺，二级回复缩进 + 左竖线；超过 3 条折叠为"展开 N 条更多回复"（前端即可，数据已全量返回）。
3. 回复体里显示**灰色引用行**（回复对象昵称 + 摘要），点击可滚动到被引用评论并高亮 1s。
4. 评论增加点赞（现有 reaction API 若未覆盖 comments，需后端加 comment-level vote）。
5. 楼主徽标（OP）在所有评论区显示。
6. 若社区是"问答"类：楼主在每条回复上出现"✓ 设为最佳回复"，被选回复置顶 + 绿色边框 + 列表卡片标题前 ✅。
7. 评论区排序：最热（票数）/最新。

### 4.5 Wiki（`c/[slug]/wiki/*` + `wiki/[id]/*`）★重点
**索引页：从"标题列表"变"目录卡"**
```
┌ 共建 Wiki ─────────────────────────────────────────┐
│ [搜索词条…                        ]  [+ 新建词条]   │
│ 最近更新: 图书馆攻略(2h) · 选课指南(1d) · 搬家指南(3d)│
│ ┌────────────┬────────────┬────────────┐           │
│ │ 图书馆攻略   │ 选课生存指南 │ 校园地图     │           │
│ │ 摘要两行……  │ 摘要两行…   │ 摘要……      │           │
│ │ 12节 · 5贡献者│ 8节 · 3贡献者│ …          │           │
│ │ 更新于 2h前 │ 更新于 1d前 │             │           │
│ └────────────┴────────────┴────────────┘           │
└────────────────────────────────────────────────────┘
```
**文章页：阅读优先 + 三入口**
```
┌──────────────────────────┬──────────────┐
│ 面包屑: 社区 / Wiki / 词条名 │ 本文信息卡     │
│ ──────────────────────── │ · 最后编辑者   │
│ H1 词条名                  │ · 更新时间    │
│ 摘要/首段                  │ · 修订 12 次  │
│ ── TOC（自动生成，悬浮右侧） │ · 字数       │
│ 1. 开放时间                │ [✏️编辑]      │
│ 2. 借书规则                │ [🕘历史]      │
│ 3. 自习室                  │ [💬讨论]      │
│ …                        │              │
│ 正文（wikilink 蓝链已支持）  │ 相关词条       │
└──────────────────────────┴──────────────┘
```
交互步骤设计（回答"wiki 应该如何显示"）：
1. **索引页**：卡片含摘要（正文前 80 字）、章节数、贡献者数、更新时间；顶部"最近更新"一行 + 搜索框；空态引导"从你熟悉的一个概念开始"。
2. **阅读页**：右侧栏固定"本文信息卡 + 编辑/历史/讨论三入口"；正文按 H2/H3 自动生成 TOC（正文 >3 个 H2 才显示），当前章节高亮。
3. **编辑**：编辑器沿用现有 `WikiEditor` + `ConflictResolver`；提交前显示 diff 预览；保存后 toast"已保存为第 N 版"。
4. **讨论**：每词条带讨论区（复用帖子评论组件，锚定词条），避免"知识"和"闲聊"混在正文。
5. **wikilinks 点击新建**：正文里 `[[]]` 链接若目标不存在，点击进入"创建词条"预填标题——这就是"知识在编辑中生长"的最顺滑路径。

### 4.6 消息 / 通知
- 顶栏 🔔 → 下拉面板（前 8 条）+ "查看全部"页。
- 聚合文案：'A、B 和另外 5 人回复了你'；未登录不显示入口。
- 暂时复用现有通知 API，聚合逻辑前端做。
