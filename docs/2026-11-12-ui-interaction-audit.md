# 用户侧与管理侧 UI 交互审查

审查时间：2026-11-11 至 2026-11-12（Asia/Shanghai）。本报告是设计审查，不是上一轮功能回归测试的重复结论。

## 结论与范围

记录 16 个可改进项：2 个 P1、13 个 P2、1 个 P3。P1 为可能造成输入丢失或管理误判的优先事项；P2 为日常操作的理解、导航、反馈和一致性问题；P3 为布局打磨。设计风险不等于已经发生误操作。

检查了账号菜单、切换账号及注册分支、取消焦点、通知空状态、账号设置、隐私页签、发帖校验、私信空状态、全站举报队列、用户详情、处罚菜单与确认区、群组、站点设置、未保存导航和 390px 窄屏布局。共保存并查看 19 张截图。

前四张截图来自本次审查开始时的原演示账号。恢复工作时，本地服务停止，启动现有 MySQL 后原演示库不可用；后续用现有迁移和专用临时账号重新准备本地审查数据。未连接线上环境，未模拟页面响应。临时账号已退出、测试数据已清理；业务界面代码未因本报告而修改。

## 建议的切换账号流程

头像菜单采用切换语义图标 → 展示当前账号并选择“登录其他账号” → 输入其他账号 → 主按钮“登录并切换” → 成功后明确提示已切换到谁，随后刷新当前页面的数据。

取消和失败都保留当前登录身份；关闭回到原入口。注册与找回密码应明确离开当前切换任务。若以后加入最近使用账号列表，只保存必要的展示信息，不把明文凭据作为实现方案。

## 已有优点与验证边界

已有优点：切换提示明确说明取消保留账号；私信空状态提供解释与发起入口；发帖底部保持主次动作；处罚确认要求原因并聚焦输入框；管理设置在同模块内部切换时保留草稿。

可访问性：确认了切换弹窗的焦点回退问题及发帖错误的焦点未定位。截图只能提示对比度和点击目标风险，不能据此宣称达到或未达到完整 WCAG 标准。尚未完成读屏、所有键盘组合、真实触屏与多浏览器检查。

范围边界：未逐页遍历所有 Wiki、举报详情、申请状态、版主/助手专属工作流；未提交实际处罚、注销、站点设置，也未模拟网络错误。原数据不可用后的截图使用临时审查数据，不能作为真实内容丰富场景的视觉证明。测试帖出现的 `NaN 天前` 与测试夹具时间字段有关，未列入已确认产品问题。

优先顺序：先处理 A01/A02 和 U02/U04，再统一账号动作、菜单、错误反馈与导航规则，最后处理空状态和窄屏布局。完整问题清单中“已观察现象”和“建议”分开，不把建议当作现有缺陷。
