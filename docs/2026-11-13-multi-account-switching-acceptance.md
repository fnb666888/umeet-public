# 多账号记忆与切换验收

日期：2026-11-13。已实现并在本机隔离环境验证；未部署正式环境。

## 使用方式

打开 <http://127.0.0.1:5178/>，点击头像 → 切换账号。

- 首次点击“添加其他账号”并正常登录；有效期内，之后点击列表中的账号即可切换。
- 最多保存 5 个账号，包含当前账号。重复登录更新原名额，第六个明确拒绝，不替换旧账号。
- 同一浏览器、同一站点的 Umeet 标签页统一切换。切换后返回社区或 Wiki 首页，管理页不会保留旧身份操作界面。
- 过期账号保留名称并显示“重新登录”；重新验证不增加名额。
- 退出当前账号仍可选择其他已记住账号；移除某账号只撤销此浏览器的授权；退出所有账号清空本浏览器列表。
- 当前账号标记、动态角色范围、取消、错误提示、键盘 Escape 与焦点返回均已接入。账号面板适配桌面和手机。

本地账号和随机密码位于 `rebuild/.runtime/local-role-accounts.md`，该目录被 Git 忽略。账号包括管理员、物理学版主、物理学助手、普通用户 A、普通用户 B。版主与助手采用真实板块及团队授权，不依靠前端角色伪装。用户浏览器首次添加时仍需正常登录，测试浏览器的 Cookie 不会复制到用户浏览器。

## 会话与数据保护

新增迁移 `034_browser_accounts`。服务端维护浏览器集合与最多五条记忆登录授权；记忆授权引用不能直接访问 API 的 backing session，活动账号使用轮换的子会话。数据库仅保存凭证摘要。

浏览器仅通过 HttpOnly、SameSite=Lax Cookie 持有设备凭证与活动会话；正式构建启用 Secure。页面 JSON、localStorage、sessionStorage 不保存密码或登录 token。localStorage 中的标签页登记只含随机标签页 ID 和时间。

切换继承原始绝对到期时间与认证时间，不通过切换延长登录或绕过十分钟内重新验证。改密、密码找回、远程注销、停用及删除可使原授权失效；“退出其他设备”与解除登录绑定保留当前设备的 backing session。设备列表合并子会话，只展示一个当前设备。

集合事务锁和版本检查防止并发添加突破五名额。浏览器写请求必须携带发起时的账号和版本，带绑定的读取同样检查，旧页面不能把新 Cookie 当成原身份使用；慢响应在身份变化后不再交给业务界面。账号列表发现身份变化时刷新业务树，不原地给旧界面绑定新身份。原生、小程序独立会话沿用原认证方式。

切换前通过 BroadcastChannel 协调所有标签页。Wiki 草稿等待服务器保存，发帖草稿按账号保存在本机，社区操作队列先完成；站点设置、板块设置和其他未提交输入允许取消离开。保存失败或其他标签页未确认时取消切换。Web Locks 判断存活标签页，避免开发模式的重复初始化留下“幽灵标签页”；不支持时使用心跳登记。焦点复核与服务端校验处理漏收广播，发起页崩溃后的等待状态有超时恢复。

## 后续运行

当前预览地址继续使用 5178，API 使用 3188，数据库为 `umeet_rebuild_test_knowledgebrowser`。重新配置测试角色用 `npm run accounts:local`。浏览器专项用 `npm run e2e:accounts`，需先运行本地预览，并保留 Wiki 及账号 fixture 元数据。

正式上线前需将新增迁移随 API 发布，配置 HTTPS 与 `PUBLIC_WEB_ORIGIN`，再部署 Web；本次未执行这些上线操作。清除浏览器 Cookie 或使用另一个浏览器配置文件后，需要重新添加账号。
