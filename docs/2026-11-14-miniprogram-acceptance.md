# 小程序本地实施与验收记录

日期：2026-11-14。范围：普通用户与 Wiki 原生小程序；管理仍使用网页后台。模拟器验收已通过，按用户授权推进发布；生产结果需另行确认。

## 已实现

- 社区、Wiki、消息、我的四个底栏入口，使用网站蓝白设计变量与线性图标，支持深浅主题；20 个原生页面。
- 新版统一 Bearer 会话，同网站用户与内容；密码登录、可配置的邮箱注册/找回、显式微信关联。未启用的通道不伪造成功。
- 社区分页、搜索、详情、回复、点赞收藏、举报、分享、发帖图片、个人记录与资料隐私设置。
- 发帖重试使用稳定标识；成功后不重建草稿；编辑草稿保留原帖 ID；大图草稿使用本地文件，失败明确提示。网站长富文本可完整阅读，编辑通过 Markdown 转换并复用原写入权限。
- 私信分页、请求接受/忽略、双向发送、屏蔽、免打扰与举报；通知与私信分开，打开通知标为已读。
- 板块申请、退回重提、版主/助手邀请、管理记录与申诉，复用现有服务权限。
- Wiki 搜索、词条、社区目录、学习路线、关系及条件、历史差异、讨论纠错；Markdown 与原生 PNG 公式。
- Wiki 创建/修改、模板、关系检索、预览、服务器私人草稿、本机未同步备份、版本冲突比较/另存、提交审核与退回重提。普通用户不直接覆盖已发布正文。
- 客户端会话变化丢弃旧请求；登录与退出清空页面栈；401 退出到登录页；私人草稿按账号隔离。

## 续验结果与发布

2026-11-14 用户授权“完成所有模拟器验收后直接发布上线”。先前将导航故障归因于自动化连接不准确；整包截图确认，实际是格式化器把 Wiki 历史页模板表达式中的字符串拆成两行，阻断整包编译。已合并模板表达式并增加静态检查，防止再次出现。

最后版本已完成：

- 20 个注册页面逐页原生运行检查，未出现页面错误。
- Wiki 退回、补充、正文冲突核对、重提、审核通过、公开阅读。
- 社区目录、路线下一步、关系检索添加、两版历史差异。
- 图片选择（仅系统选择器使用固定图片模拟）、本机草稿恢复、实际发布与共享 API 图片持久化。
- 深色主题与公式、个人资料写入、申请与治理记录页。
- 请求失败时保留本机输入、恢复后重新同步；私人草稿并发冲突比较、另存且不覆盖服务器稿。
- 隐藏词条后明确显示不可用并清空页面旧内容，恢复后可阅读。
- 超过 2000 字的原生帖子编辑及完整正文保存。

模拟器操作使用与正式服务相同的本地隔离后端。全部模拟器验收通过后开始 GitHub 发布流水线，API、网站和小程序的自动检查均设为门禁。

真实微信 code 登录/绑定、邮件实际投递、手机分享和平台审核仍属于外部平台/真机环节，不能以模拟器代替。小程序上传代码不等于微信已审核发布；最终发布状态以后续平台实际结果为准。

## 本地复现

1. 根目录运行 `npm run build --workspace=@umeet/miniprogram`、`npm run check:mini`、`node --test tests/mini/session.test.mjs`。
2. 新版后端位于 `rebuild`，运行 `npm run build:api`、`npm run typecheck`、`npm test`，不要误用根目录的旧 API 构建命令。
3. 隔离预览库为 `umeet_rebuild_test_minibrowser`；首次准备可在 `rebuild` 运行 `node --import tsx tests/web/knowledge-fixtures.ts --mini`。此命令会重建该测试库，继续现有验收时不要重复执行。
4. `rebuild` 中运行 `node scripts/run-miniprogram-preview.mjs`，启动本地 3188 API 与 5178 BFF。测试身份只在忽略的 `.runtime/mini-knowledge-fixture.json`，不包含在小程序包。
5. 微信开发者工具打开项目根目录，构建目录为 `apps/miniprogram/dist`。本地开发接口为 `http://127.0.0.1:5178/api/mobile`，仅私有开发配置关闭域名校验；正式版本仍为 HTTPS，未部署验证。
6. 网站颜色变量同步：根目录运行 `node scripts/sync-mini-tokens.mjs`；图标生成：`node scripts/generate-mini-icons.mjs`。
