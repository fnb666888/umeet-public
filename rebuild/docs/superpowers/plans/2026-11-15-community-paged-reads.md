# 社区分页读取实施计划

**Goal:** 将首页、普通板块列表与帖子详情从全站快照读取迁移到有上限的页面读取，保持账号隔离、隐藏内容、排序与写入后的更新正确。

**Architecture:** 在现有实体存储上增加自动更新的索引列；帖子保存时同步活动、回复数和点赞排序字段。新增 feed、post 页面接口，列表每页 20 条、回复每页 50 条，以稳定排序键和 ID 为游标。页面只读取当前账号状态、当前页作者和投票信息；其余社区页面暂保留兼容快照。

**Tech Stack:** Next.js 16 / React 19 / NestJS / Kysely / MySQL 与 TiDB。

**Spec:** 本会话用户确认的“首页分页 → 详情按需读取 → 当前页个人状态 → 解除完整快照依赖”方案。

## 约束与风险

- 数据库分页，禁止将全站内容读取到 Node 再截取。
- 隐藏帖子不得泄漏正文，隐藏回复和引用必须脱敏。
- 热门、最新、活动、关注、板块和标签筛选保持正确，游标绑定查询条件。
- 写入与账号切换后旧缓存不得覆盖新数据；默认首页 HTML 含首屏内容。
- 现有其他页面必须仍可读取完整数据，不将一页数据误当作全站数据。
