# 原版 Demo 接入与内容切换

以 `demo/web-ux` 的 HTML、CSS、组件模板、页面路由和默认交互为验收基准。保留现有正式账号、邮箱身份和会话能力。切换后的新站从没有帖子、回复和 Wiki 词条的状态开始。旧内容留在旧数据范围供回退，Demo 的演示内容只进入界面对照预览。

## 1. 界面基准

- `scripts/bundle-demo-ui.mjs` 从原版目录打包预览文件，验证文件逐字节相等。后续接入将读取与写入放在数据适配层，沿用原模板。
- 桌面和手机分别对照首页、紧凑列表、发帖、社区、帖子详情、Wiki 以及账号菜单。视觉比较使用相同测试数据，生产空状态另做验收。

## 2. 真实账号与新内容

- `apps/api/src/modules/identity` 继续提供已注册账号与邮箱验证。原型中的固定身份由当前会话替代。公开页面使用服务端许可展示的身份，写入按账号 ID 验权。
- 为 Demo 讨论和 Wiki 建立独立数据范围。建立空内容库所需的测试只允许隔离 MySQL，验收要求原账号可登录，新帖子与 Wiki 查询为空，旧内容仍能在旧范围读取。
- Demo 的本地快照保存改为按操作发请求。先接首页、板块列表、发布、回复、点赞与收藏，再接标签、订阅、问答采纳、交易状态及 Wiki 分段与修订。使用同一帖子或词条的不同会话验证数据一致。
- 通知和私信接入真实账号关系后再启用实际写入。正式环境的附件由后端检查与授权，浏览器内的 Blob 不作为线上记录。

## 3. 切换验证

- 两个账号在隔离环境依次验证注册或登录、发布、回复、点赞、收藏、Wiki 编辑、搜索和刷新后恢复。帖子和 Wiki 不从演示数据加载。
- 站点切换保留之前版本的可回退路径。上线前核对正式域名、邮箱验证码、新站为空以及旧账号正常登录。

## 2026-11-08 实施记录

首页外壳和邮箱登录窗口已迁入 Next.js 的 React 组件，原 Demo 的内部页面模板与交互脚本由该入口按顺序加载。此次上线采用过渡式接入，内部页面仍由原脚本渲染，逐组件 React 化尚待继续。

写入使用经过校验的操作批次。服务端根据会话填入作者、时间和修订记录，帖子状态仅作者可改。批次使用请求摘要去重，Wiki 用修订号防覆盖。内容按实体存于新表，图片单独存储并验证格式。账号继续使用现有身份表。新内容范围初始为空。

本地双账号接口验收覆盖权限、重试、并发点赞、Wiki 冲突、私信隔离和图片。浏览器覆盖发布、跨账号回复、刷新、收藏、采纳、Wiki 编辑与历史，以及四种屏幕宽度。
