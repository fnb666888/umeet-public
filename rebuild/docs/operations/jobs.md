# 持久化任务与上传限额

API 启动后运行一个 MySQL 任务处理器；每个 API 实例有独立 worker ID。无需第三个服务、Redis 或内存队列。测试应用默认不启动轮询；生命周期集成测试显式启动同一个生产处理器。

## 执行约定

- 业务事务中调用 `OutboxService.recordEvent(tx, event)`，或 `JobsService.enqueue(tx, input)`。事件必须带业务对象和版本 ID，幂等键重用但内容不同会报错。事务失败，事件一起回滚。
- 任务数据禁止包含密码、验证码、会话 token、邮件/短信供应商密钥和匿名作者身份关联。具体处理器应以严格 DTO 验证 payload，并根据 ID 读取业务对象的当前版本和公开权限。
- 使用 `FOR UPDATE SKIP LOCKED` 领取一条任务，租约 60 秒，执行中每 20 秒续租。数据库调用不包住外部网络请求。未配置的处理器不会返回假成功，而会以 `HANDLER_UNAVAILABLE` 重试。
- 失败采用指数退避，最多 5 次；进程崩溃也计入尝试次数。第 5 次崩溃的租约过期后转失败。损坏的 JSON 任务直接隔离为失败，避免永久堵住队列。
- 处理器收到 `AbortSignal` 应尽快终止外部请求。丢失租约后不能确认完成或重试。数据库副作用必须通过 `withLease` 事务执行，并使用业务唯一键去重；事务提交前再次校验有效租约。
- 外部服务调用需要供应商支持幂等键，或业务层去重/对账。租约不能保证外部副作用“恰好一次”；调用成功而确认任务前崩溃仍可能重试。
- NestJS 关闭流程先停止领任务、发送中止信号并最多等待 30 秒，再释放数据库连接。未确认的工作由持久化租约恢复。处理器不可无限忽略中止信号。

正式启动默认开启处理器。后续内容检查、索引和通知模块需显式注册自己的真实处理器；当前未接入任何假审核、假通知或假存储。已有失败任务不会因代码更新自行删除。

## 管理接口

接口要求服务端解析出的正式账号具有 `owner` 或 `admin` 平台角色；不能通过请求体指定角色。网站同源代理及管理页面在管理后台任务中接入。

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/admin/jobs?state=failed&after=…` | 每页最多 50 条安全摘要；不返回业务键或 payload |
| `GET /api/v1/admin/jobs/stats` | 排队、执行、完成、失败数，过期租约数和最早排队时间 |
| `POST /api/v1/admin/jobs/:id/retry` | 仅重试失败任务，提交 `{"reason":"修复配置后重试"}` |
| `GET /api/v1/admin/settings/limits` | 读取版本号与上传限额 |
| `PUT /api/v1/admin/settings/limits` | 提交基础版本号、完整限额及原因 |

手动重试将本轮 attempts 归零，但保留最近错误码，并把原尝试次数、错误码及操作原因写入审计。不可通过重试接口重新运行已成功或正在执行的任务。检查失败原因、处理器依赖和业务幂等性后再重试。

上传限额初始值：单文件 100,000,000 字节，账号在上海业务日累计 200,000,000 字节，允许新上传。管理员可暂停新上传或调整额度。设置即时以数据库为准，不依赖任务传播；多个管理页面同时保存，旧版本返回 `SETTINGS_VERSION_CONFLICT`。资源模块会消费该设置；这一步没有声明资源上传功能已完成。

## 验证依据

真实 MySQL 覆盖并发领取、重启恢复、租约过期/续租、旧租约拒绝、重复崩溃封顶、损坏任务、事务回滚、大 payload、限额并发修改和后台权限。调度单测验证续租失败中止以及关闭期间不开始新处理器。API 生命周期测试使用真正的 NestJS 启停过程。

实现参考 [MySQL 锁定读取](https://dev.mysql.com/doc/refman/8.4/en/innodb-locking-reads.html) 与 [NestJS 生命周期](https://docs.nestjs.com/fundamentals/lifecycle-events)。MySQL 默认事务隔离仍保持不变；领取前不做全队列批量更新，以免多实例在无匹配行时竞争范围锁。
