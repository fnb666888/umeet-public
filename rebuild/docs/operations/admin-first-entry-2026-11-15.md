# 后台首次进入性能修复

用户补充：长时间加载只发生在第一次进入，随后切换正常。本次针对首次进入链路，不以已预热的菜单切换速度作为验收指标。

## 已确认原因

业务 fetch 拦截器在初始化时等待完整 accounts 回复；后者包含所有已保存账号的权限图和状态检查。后台随后串行请求 access 和 items，每次分别认证并读取权限。默认队列的 HTML 原先只包含加载提示。

## 修改

- 新增 auth/browser/context，只验证当前会话并返回设备、账号和版本。账号菜单仍使用完整 accounts 接口，切换、封禁和过期检查保持服务端验证。
- admin/community/bootstrap 在一次认证和授权后返回权限与当前列表。深链接使用同一接口，返回数据按账号和版本隔离。
- 默认 /admin 首屏在服务端读取授权队列，将真实内容放入 HTML；浏览器确认当前身份后写入内存资源缓存，避免再次获取相同列表。
- 会话的浏览器有效性检查、限制检查和角色查询并行执行。仍需全部成功才返回身份，无跨请求权限缓存。

## 验证

1. 每次 SQL 人工增加 140 ms：旧流程 accounts → access → items 为 2113 ms / 47 次查询；context → bootstrap 为 1200 ms / 24 次查询。此对比在认证并行优化后的相同版本代码中执行，未将这部分改动的收益额外计入。
2. 本地生产构建，新浏览器上下文，accounts 人工延迟 3000 ms：旧首屏 3240 ms，新首屏 197 ms。无延迟新首屏 242 ms。页面 HTML 中没有“正在加载管理数据”，且未重复发送首屏 items 或 bootstrap 请求。等待账号列表完成后页面保持正常。
3. 60 个页面入口及刷新、12 项导航和后台菜单点击检查，无页面失败和 JavaScript 错误。另通过返回前进、发现、草稿保留、设置离开保护、账号切换及退出测试。
4. 前端 55 项测试通过；后端相关 33 项测试通过，包含权限撤销、会话撤销、账号和管理功能；类型检查及 API/Web 生产构建通过。

本地耗时不代表公网已登录后台耗时。线上发布后完成公开页面、导航和未授权 401 检查；当前无可用的已登录线上浏览器会话，未冒充用户或创建生产管理员来测量。
