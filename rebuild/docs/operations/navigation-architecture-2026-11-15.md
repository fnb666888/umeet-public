# Navigation architecture — 2026-11-15

The root now retains community/messaging state and server-rendered identity. Canonical /community/ routes, delegated links and imperative community commands all use the client router. Old hash bookmarks redirect once on document entry. Root-only bootstrap is skipped on client RSC transitions.

ResourceDomain provides account/device/version-scoped memory, canonical query keys, shared pending reads, bounded entries, consumer cancellation, stale display and generation-safe invalidation. Identity changes evict visible data and restart readers; old authorization failures cannot evict the next account cache. Admin, Wiki, interest, account, governance, applications and messaging transport use this shared service. Polling messages always revalidate. Writes invalidate registered resources. Forms remain independent, and dirty site settings resist late refreshes. Intent prefetch has two background slots and hover/focus priority; foreground reads execute directly.

Anonymous bootstrap reads at most 20 visible posts, 200 related replies, relevant authors and hidden-reply targets. It does not enumerate account preferences or private messages. Hidden replies, images, quoted hidden bodies and hidden accepted answers are masked. Current member identity is present in initial HTML.

Boundary: authenticated community operations still use the existing full snapshot API. This change reuses it across routes and removes it from anonymous first paint, but does not yet replace every operation with paginated domain APIs. Growth in posts/users can still increase cold-read cost. Uncached protected pages can require a loading state; remote database and network latency remain. No claim of zero network time or full major-site infrastructure parity.

Verification: 53 frontend tests in 16 files; TypeScript; API/Web production builds; 4 API bootstrap/privacy/snapshot/query-budget tests in 3 files using an isolated local database. Production browser audit covers 60 route entries and reloads, 5 community links, 7 admin sections and safe button probes. It does not click destructive actions or cover every data-dependent button.

Browser regressions cover actual community/board/post/Wiki/admin clicks in one document, back/forward, comment anchors, home filters, reply drafts, unsaved settings cancellation, direct query URLs, old bookmarks and delayed Wiki API responses. Community snapshot requested once across the transition chain. Initial identity was verified without JavaScript and with browser accounts delayed 3 seconds. QA account switching, correct settings identity, direct admin entry, logout and anonymous admin rejection passed.

Latest local production audit: no route failures or browser exceptions; max document readiness 311 ms, max reload readiness 185 ms; client transition chain 48–99 ms. Local database results are not public-network guarantees or Core Web Vitals scores. Public deployment evidence is separate.

No schema migration, paid service or provider change. Source archives exclude secrets and unrelated projects.
