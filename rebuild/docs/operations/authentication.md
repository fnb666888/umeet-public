# 自管认证与验证码发送配置

认证、身份映射和会话由 NestJS/MySQL 管理，部署仍是微信云托管的网站/API 两服务，不使用 CloudBase 认证。用户已选择先完成代码与模板、稍后准备发送服务。邮箱和短信默认关闭；本文件及示例没有实际凭据，也不会购买或创建发送服务。

## 两个服务分别配置

API 使用 [api.env.example](../../deploy/cloudhosting/api.env.example)，网站使用 [web.env.example](../../deploy/cloudhosting/web.env.example)。实际密码和服务密钥放微信云托管的安全环境配置中；不要上传到 Git，不要加 `NEXT_PUBLIC_`，也不要放进小程序包。示例主机名/数据库账号必须替换，服务端口须与控制台设置一致。

网站只需 API 地址和允许的 HTTPS 网站来源。数据库、验证码摘要密钥、微信 AppSecret、SMTP 和短信凭据只给 API。

`npm run auth:check` 只检查配置并输出开关/额度，不发送消息，也不打印密钥。`npm run auth:check -- --require=email,sms` 会在任一渠道未配置时失败。启用一个渠道但缺少必需配置时，API 拒绝启动；未启用的渠道返回明确的不可用状态，网页按钮保持禁用。

## 邮箱：通用 SMTP

准备真实 SMTP 发件服务后设置：

| 环境变量 | 含义 |
| --- | --- |
| `EMAIL_OTP_ENABLED=true` | 明确启用邮箱验证码 |
| `OTP_HASH_KEY` | 独立随机32字节，编码为64位十六进制，仅服务端保存 |
| `SMTP_HOST`、`SMTP_PORT` | 实际服务器与端口 |
| `SMTP_SECURITY` | `starttls`（通常587）或 `tls`（通常465） |
| `SMTP_USER`、`SMTP_PASSWORD` | SMTP账号和密码/授权码 |
| `SMTP_FROM` | 服务允许使用的发件邮箱 |

实现保留证书和主机名验证；STARTTLS 模式强制加密升级，不提供关闭证书校验或日志输出验证码的开关。只有目标收件人被 SMTP 接受才确认提交发送，不能据此宣称已经到达收件箱。参考 [Nodemailer SMTP说明](https://nodemailer.com/smtp)及[发送结果说明](https://nodemailer.com/)。

邮箱只统一域名大小写，保留本地部分；身份映射使用区分大小写的数据库字段。不按昵称自动合并账号。

## 短信：默认关闭，可替换发送器

尚未选择实际短信供应商。代码附带一个**可选**腾讯云短信适配器，`SMS_OTP_PROVIDER=disabled` 为默认值。这只是可替换的消息发送器，不改变微信云托管部署，不要求另接 CloudBase，也没有开通短信资源。

将来如果选择该适配器，设置 `SMS_OTP_PROVIDER=tencent`、`OTP_HASH_KEY`，并填写 `TENCENT_SMS_SECRET_ID`、`TENCENT_SMS_SECRET_KEY`、`TENCENT_SMS_APP_ID`、`TENCENT_SMS_SIGN_NAME`、`TENCENT_SMS_TEMPLATE_ID`。区域默认 `ap-guangzhou`；模板变量设 `TENCENT_SMS_PARAMETERS=code` 或 `code,minutes`，须与实际获批模板一致。签名、模板和发送权限需要另外核验，参考[供应商官方 SDK 文档](https://cloud.tencent.com/document/product/382/56060)。

手机号要求 E.164 格式，例如 `+8613800000000`，不会替用户猜区号。非 `+86` 号码必须另外配置 `TENCENT_SMS_INTERNATIONAL_TEMPLATE_ID`，可补充国际签名和 Sender ID；缺少国际模板时不会偷偷使用境内模板。更换供应商只需实现 `OtpSender` 并接入配置工厂，业务账号和验证码事务保持不变。

## 业务规则与费用控制

- 验证码6位、有效10分钟，只保存带独立密钥的 HMAC 摘要，HTTP响应和应用日志不包含明文验证码。
- 同一目标60秒后才能重发，每小时最多6次；网站/API入口另有持久化请求限制。重发使相同用途的旧验证码失效。
- 同一挑战最多尝试5次，失败次数会提交到数据库；成功消费与账号/会话写入在同一事务，不能并发重复使用。
- 上海业务日的默认发送尝试上限：邮箱200次、短信20次。可用 `OTP_EMAIL_DAILY_LIMIT` / `OTP_SMS_DAILY_LIMIT` 调整，0表示暂停该渠道的新发送。失败尝试也占额度，避免供应商已受理但本地超时后重复消耗。该计数不是费用报价或绝对账单上限。
- 绑定要求近期10分钟内验证过的正式账号，同时校验新邮箱/手机号；不能把已属于其他正式账号的身份移过来。
- 网页注册使用独立 register 用途，提交唯一用户名、密码与邮箱验证码，游客升级保留数据。邮箱验证码登录面向已注册账号。设置或修改密码使用 password 用途的绑定邮箱验证码，已有密码还需要原密码。更新密码后签发新会话并撤销旧会话。
- 更换 `OTP_HASH_KEY` 会使旧摘要不再匹配，应避开仍有有效验证码的窗口；已有账号会话不依赖此密钥。

## 本地验证与尚未完成的事项

`npm run check` 包含真实隔离 MySQL 的有效期、错误次数、并发消费、发送预算、绑定归属、会话撤销和近期验证测试。发送器单元测试使用测试内的传输替身，生产没有 `console`、`fake` 或返回验证码的登录模式。

网站邮件流程另用真实本地 TLS SMTP sink 验证。按顺序在不同终端运行：

1. `node scripts/prepare-smtp-fixture.mjs`：生成仅一天有效的本地证书和私钥，文件位于忽略的 `.runtime/smtp-fixture/`。
2. `npx tsx tests/web/support/smtp-fixture.ts`：只监听回环地址，只接受 `@fixture.invalid`，不转发邮件。
3. 停止普通本地 API 后，运行 `node scripts/run-smtp-test-api.mjs`。它使用正常 API、回环测试数据库及本地 TLS 信任证书，不关闭 TLS 校验，也没有身份验证绕过。
4. 保持网站开发服务运行后执行 `npm run e2e:web:otp`。浏览器从测试私有投递文件读取验证码，测试升级、绑定、冷却时间和同账号登录；这个文件不会进入仓库。
5. 结束后停止测试 API 和 SMTP fixture，再以普通配置启动 API，邮箱和短信恢复默认关闭。`npm run e2e:web` 另跑常规账号/Wiki流程。

本地 SMTP 协议通过不代表真实邮件服务已验收；短信发送、真实微信、小程序/网站身份绑定及整体验收仍须使用实际配置验证。没有修改线上服务或发布新版本。

## 网页账号生命周期

网页登录支持邮箱验证码，以及已设置密码账号的邮箱或用户名密码登录。设置中的账号与安全提供密码设置、密码修改及已验证邮箱管理。密码要求 12–128 个字符。设置密码后轮换当前会话并撤销旧会话，登录用户名沿用账号已确认的用户名或历史密码凭据标识。

忘记密码入口使用独立 recovery 用途。只有已绑定邮箱可以恢复原账号，验证码请求使用统一提示，未绑定邮箱不会创建账号或发送恢复邮件。找回表单一次提交验证码和新密码，验证成功后完成密码重置并建立新会话。验证码仍遵循十分钟有效、五次失败上限、六十秒重发间隔和发送预算。

注销需要十分钟内验证过的身份和准确输入注销我的账号。注销立即生效，清除密码、外部身份、全部会话、个人资料和私人收藏记录。本人发送的私信替换为注销提示。公开帖子、回复及可明确归属的 Wiki 贡献保留，作者显示已注销用户。用户名保留占位以避免冒充。新增 Wiki 编辑记录、建议和注释保存作者 ID。
