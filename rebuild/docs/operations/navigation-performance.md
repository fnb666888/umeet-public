# 页面切换与账号初始化性能修复

日期：2026-11-15。候选版本：`/opt/umeet/releases/20261115-navigation-perf`。

## 原因与修复

杭州 ECS 到现用 TiDB 的单次查询约 140 ms。社区快照、板块目录、权限与账号列表中互不依赖的读取串行执行，耗时逐项累加。前端每次 hash 路由切换还会重新请求整份社区快照。

- 并行读取社区快照各部分、板块目录、权限查询及各已保存账号的展示状态，连接池上限仍为 5。
- 社区接口的快照、昵称和管理范围并行读取。
- 同一切换事务中复用已认证的新会话 actor，避免立即重复认证同一个 token；事务边界、锁和身份版本校验保留。
- 同一页面实例复用当前账号快照 30 秒，路由切换立即展示现有数据，过期后后台读取；窗口重新聚焦也检查是否过期。写入成功仍立即更新快照，手动刷新不受 30 秒限制。
- 账号切换仍重新加载文档，不把账号私有快照保存到浏览器持久存储。初次读取未完成时的快速切页合并为一次读取。

## 对比与验证

在 ECS 上用同一数据库、预热的连接池，依次调用旧版及候选版本服务。仅读取数据，不创建账号、不发消息、不修改生产记录。

| 服务读取 | 旧版 | 候选版本 |
| --- | ---: | ---: |
| 登录用户社区快照（省略私信） | 1659 ms | 527 ms |
| 已保存账号展示状态（1 个账号） | 1210 ms | 648 ms |

这是一次服务层对比，不是完整浏览器登录耗时或持续负载测试。多账号写入仍需事务串行执行，数据库网络往返仍然存在。

本地类型检查、API 构建通过。前端 32 项测试通过；相关后端 25 项测试通过，覆盖社区、账号切换、管理权限、管理组、社区治理及团队管理。新增回归验证查询并行、快速切页请求合并、过期刷新及页面实例销毁后的重新读取。

服务器 Linux Web/API 构建通过。用户确认“直接发布”后，2026-11-15 16:15（Asia/Shanghai）切换至上述版本并重启 `umeet-web` 和 `umeet-api`，健康检查通过，无需数据库迁移。上一版本路径保存在版本目录的 `.previous-release`。

## 后台导航补充修复

首轮发布仅优化了读取与社区 hash 路由，未覆盖后台的加载依赖。复查发现 `AdminWorkspace` 每次换菜单都清空列表，同时等待 overview 和 items；部分跨页面链接使用普通锚点，触发整个文档重载，账号 Provider 又从未就绪状态开始。社区快照也仅在组件实例内保留，退出再进入时丢失。

已发布版本 `/opt/umeet/releases/20261115-admin-navigation` 修复如下：

- 主要站内导航使用 Next Link，保留根布局和账号 Provider。
- 统计独立加载；菜单切换不再重读统计，板块名称读取也不阻塞主列表。
- 管理 GET 与社区快照在内存中保留 30 秒，按浏览器设备、账号、身份版本隔离，最多保留 100 项；不使用持久化存储。
- 管理写入与手动刷新使缓存失效，旧请求不得在失效后重新填入缓存；过期菜单重新请求。首次访问未缓存页面仍需要读取数据。
- 板块、搜索、筛选、页码、记录 ID 均包含在管理读取键中，防止复用其他视图的结果。

37 项前端测试及类型检查通过。新增测试先复现了旧版本“统计未返回导致列表不可见”“切换三次请求三次统计”的问题。隔离本地数据库上的真实 Edge 浏览器流程“社区 → 后台 → 用户管理 → 内容管理 → 社区”验证：文档加载 1 次、账号初始化 1 次、社区快照 1 次、统计 1 次、举报列表 1 次、用户列表 1 次，页面全局标记保留，脚本错误 0。用户身份仍由服务器验证，真实账号切换依然清空页面以隔离私有状态。

架构限制：API 部分管理列表仍复用宽泛的数据汇总，再在内存过滤/分页；ECS 与数据库的网络往返约 140 ms。这些会影响首次进入、冷请求及数据规模扩大后的速度，本次没有进行数据库迁移或管理查询模型重写。Discourse 的前端路由与 JSON 数据加载机制可参考其[官方开发指南](https://meta.discourse.org/t/creating-routes-in-discourse-and-showing-data/48827)。
