# 微信云托管的产品边界

最新决定（2026-11-07）：用户明确选择由NestJS维护登录，不另接CloudBase。托管认证候选已撤回；后端接入微信、邮件、短信的实际凭据与发送能力仍需验证。

2026-11-07 用户再次明确：使用微信云托管，不是把部署迁入腾讯云控制台或 CloudBase 云开发环境。

- 部署目标是微信云托管现有账号下的网站/API两个服务；真实环境身份与权限需要在该产品管理路径核实。
- CloudBase MCP 的账号登录成功仅说明该工具获授权。其“没有CloudBase环境”的结果不证明微信云托管没有环境。
- 本次未创建CloudBase环境、修改登录provider、部署容器或切换线上流量。
- CloudBase托管认证是此前讨论过的外部认证候选，需要独立判断兼容性和成本；不能推断微信云托管内置或已经开通该认证产品。
- 在微信云托管管理能力明确前，继续本地MySQL、编辑器与业务规则的实现和测试，不用其他产品的开通流程绕过。

已找到旧项目使用的官方 `@wxcloud/cli` 微信云托管专用入口。2026-11-07以只读`service:list`返回`umeet`和`example-api`，均为normal。`scripts/wechat-hosting-readiness.mjs`捕获CLI输出并只输出服务元数据，不显示凭据，不执行部署/新建/配置修改。该结果才用于微信云托管准备状态记录，不要求开通CloudBase环境。

认证实现现在直接使用 NestJS/MySQL 的密码、游客与不透明会话。微信小程序适配走微信官方 code2Session 后签发同一种业务会话，不依赖 CloudBase 认证、云数据库或 CloudBase MCP。项目源码和依赖中没有 CloudBase 运行时。原生微信真实登录和其他渠道仍需分别验收，配置存在不等于验收通过。
